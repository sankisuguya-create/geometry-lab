# 図形学習ラボ 実装引き継ぎ書

## 1. この文書の目的

小学3年生が、タッチペンまたは指で図形を動かし、考えを書きながら、円・二等辺三角形・正三角形の性質を探究するための軽量Webアプリを作る。

この文書は、クラウド版Codexに渡して実装を進めるための唯一の基準である。実装時に仕様が曖昧なときは、次の優先順位で判断する。

1. 児童が画面を見ただけで次の行為を判断できること
2. 児童用端末で軽く、通信不良でも中断しにくいこと
3. 教師が準備・説明・回収にかける時間を増やさないこと
4. 既存機能を壊さず、後の学年・単元へ増設できること

「多数の図形ツールを搭載すること」は目的ではない。紙の代替ではなく、紙では繰り返しにくい変形・重ね合わせ・比較を行う**図形の実験装置**にする。

---

## 2. 前提と制約

| 項目 | 決定事項 |
|---|---|
| 主な利用者 | 小学校3年生。初回でも教師への質問を最小化する。 |
| 端末 | ChromeOS系児童端末。4GB機を含む。タッチペン・指の両方を前提にする。 |
| 教員環境 | Google Workspace for Education。GASは使用可、Classroom APIは使用しない。 |
| 認証 | 初期版はログイン不要。児童名・名簿・学習ログをサーバーに保存しない。 |
| 通信 | 初回読み込み後は外部通信に依存しない。外部CDN、広告、分析タグを使わない。 |
| 配布 | URLまたはQRコードで開ける静的サイトとする。実際の公開先・リポジトリは未決定。 |
| 操作 | 端末のピンチズームやブラウザのスクロールによる誤操作を、作業領域内で防ぐ。 |
| 評価 | 自動採点しない。操作中の試行錯誤と、最後の短い言語化を尊重する。 |

### 非目標

- GeoGebraのような汎用作図ソフト
- 定規・コンパスの技能を端末だけで完結させること
- リアルタイム共同編集、教師ダッシュボード、名簿連携
- 児童ごとの継続的な成績収集
- 初期版からの全学年・全図形対応

紙で定規やコンパスを扱う授業は残す。アプリは、作図後に「条件を保ったまま変える」「複数の例を比較する」場面に限定して使う。

## 3. プロダクトの骨格

### 3.1 児童の画面遷移

```text
単元カード一覧
  → 課題の導入（一文の問いと開始ボタン）
  → 実験画面（図形を操作し、必要なら書く）
  → まとめ（気付きを一文で残す）
  → 画像保存 または 終了
```

画面遷移は原則この4段階に固定する。単元を増設しても、児童が新しい画面構造を覚える必要がないようにする。

### 3.2 実験画面の情報設計

| 位置 | 常時表示するもの | 表示しないもの |
|---|---|---|
| 上部 | 課題文一文、戻す | 単元一覧、設定、長い説明 |
| 中央 | 図形と操作領域 | 装飾、広告、不要な数値 |
| 下部 | その課題で必要な操作を最大3個 | 未使用の作図・測定ツール |
| 右上 | `？` のみ | 常時開いた説明文 |

実験画面での基礎操作は常に次の3つに統一する。

- **うごかす**：図形や指定された点を動かす
- **かく**：ペンで補助線、印、言葉を書く
- **もどす**：直前の状態または最初の状態へ戻る

道具名ではなく、児童が行う動詞をラベルにする。モードの切替状態は、色だけでなく、選択中のボタン形状・短いラベルで明示する。

### 3.3 初回の操作支援

- 各課題で最初に一度だけ、指またはペンで動かす対象を短くアニメーション表示する。
- 3秒以内に消え、再確認は右上の `？` から行う。
- 動画を自動再生しない。説明は1枚の図と1文を基本とする。
- 児童が誤操作しても警告ダイアログを出さない。`もどす` と `はじめから` で回復できるようにする。

## 4. 初期リリースの範囲

初期リリースは「小学3年生の円」だけを完成させる。三角形は共通基盤が安定してから追加する。

### 4.1 円の実験室

#### 学習上のねらい

円を、中心から等しい距離にある点の集まりとして捉える。円の大きさや中心の位置が変わっても、半径が一定であることに着目する。

#### 課題カード

| ID | 表示する問い | 児童ができること | 教師が期待する気付き |
|---|---|---|---|
| circle-01 | 円の上の点は、中心からどんなところにあるかな。 | 中心・半径を動かす。円周上の点を試す。 | 中心からの長さが同じ。 |
| circle-02 | 半径をのばしたりちぢめたりすると、何が変わるかな。 | 半径のつまみを動かす。 | 円の大きさは変わるが、円周上の点までの距離は等しい。 |
| circle-03 | 中心を動かしても、円であるために必要なことは何かな。 | 中心点を動かす。ペンで印を付ける。 | 中心の位置ではなく、中心からの距離が条件。 |

#### 円モジュールの必須機能

- 中心点をドラッグして移動できる
- 半径ハンドルをドラッグして大きさを変えられる
- 円周上の試行点をドラッグできる
- 「中心からの長さ」の補助線を表示・非表示できる
- 近いが円周上ではない点との比較ができる
- ペン、消しゴム、戻す、はじめから
- まとめ欄へ短文を入力できる
- 画面をPNGとして保存できる（ただし提出機能とは連結しない）

### 4.2 後続モジュール

| 順 | モジュール | 追加する中心機能 | 初期版からの再利用 |
|---:|---|---|---|
| 2 | 二等辺三角形 | 2辺を等しく保つ条件、頂点の移動、対応色 | 操作、ペン、履歴、保存 |
| 3 | 正三角形 | 3辺を等しく保つ条件、回転、比較 | 同上 |
| 4 | 面積の分割・移動 | 分ける、移す、半透明の重ね合わせ | 図形選択、履歴、保存 |
| 5 | 垂直・平行と四角形 | 方眼、直角・平行マーク、条件を保つ変形 | 点・線分・条件エンジン |
| 6 | 合同・対称・拡大縮小 | 回転、反転、重ね合わせ、倍率 | 選択・変形・比較 |

新しい単元のために既存の児童UIを増やさない。必要な道具だけを各課題が宣言し、共通の下部操作帯に出す。

## 5. 技術設計

### 5.1 原則

- ネイティブES Modulesを使う、依存関係の少ない静的Webアプリにする。
- React、Vue、Canvas描画ライブラリ、UIライブラリなどの大型依存は初期版で導入しない。
- 図形はSVG、手書きはCanvasで描く。HTMLは画面・ボタン・入力欄だけに使う。
- 作業領域は論理座標で管理し、画面サイズに応じてSVGの `viewBox` で拡大縮小する。
- Pointer Events APIを使い、マウス・指・ペンを同じ入口で扱う。
- 作業領域には `touch-action: none` を設定し、ドラッグ中のページスクロールやピンチズームを抑止する。

### 5.2 描画レイヤー

```text
HTML
├─ ヘッダー（問い、戻す、？）
├─ 作業領域
│  ├─ SVG 背景レイヤー（方眼、必要な補助線）
│  ├─ SVG 図形レイヤー（点、線分、円、多角形）
│  ├─ SVG 操作レイヤー（見えやすいヒット領域、ハンドル）
│  └─ Canvas 手書きレイヤー（ペン、消しゴム）
└─ 操作帯（最大3操作）
```

SVGを図形に使う理由は、各点・線・円を正確に選択し、条件を保って変形できるためである。Canvasを手書きに使う理由は、連続筆記を軽く処理するためである。手書きした線を図形として自動認識・自動補正する機能は作らない。

### 5.3 状態モデル

アプリの状態は、DOMから逆算せず、JavaScriptの状態オブジェクトを唯一の正とする。

```js
{
  lessonId: 'circle-01',
  activeTool: 'move', // move | pen | erase
  geometry: {
    circle: { center: { x: 420, y: 260 }, radius: 130 },
    probePoint: { x: 550, y: 260 }
  },
  options: { showRadiusGuide: false },
  inkStrokes: [],
  reflection: '',
  history: []
}
```

履歴は最大20件とする。初期リリースでは状態全体の小さなスナップショットでよい。図形数が増え、性能問題が実測された場合のみ差分履歴へ変更する。

### 5.4 データ駆動の課題定義

課題本文・初期図形・許可する操作をコードから分離する。教師用の課題作成UIは作らず、開発者がJSONまたはJavaScriptオブジェクトを追加する。

```js
{
  id: 'circle-01',
  grade: 3,
  module: 'circle',
  title: '円のひみつ 1',
  prompt: '円の上の点は、中心からどんなところにあるかな。',
  hint: '中心から点まで、線を引いてくらべてみよう。',
  allowedTools: ['move', 'pen', 'reset'],
  initialState: { /* module-specific state */ },
  reflectionPrompt: '円の上の点について、分かったことを書こう。'
}
```

## 6. UXの詳細要件

### 6.1 タッチ目標と文字

- 指で押す対象は、見た目にかかわらず最低44 CSS px四方の操作領域を確保する。
- ボタンの文言は、原則ひらがなまたは短い児童語彙にする。例：`うごかす`、`かく`、`もどす`。
- 児童画面で本文を小さく詰めない。問いは1〜2行、補助文は求められたときだけ出す。
- 色だけで「選択中」「正しい」「異なる」を示さない。線種、形、短い言葉も併用する。

### 6.2 誤操作への対応

| 事象 | 期待する挙動 |
|---|---|
| 背景を触る | 何も壊れない。ペンモードなら手書きできる。 |
| 図形を動かし過ぎる | 条件を保ったまま動く。必要なら作業領域内に収める。 |
| ペンで書き間違える | 直前だけ戻すか、消しゴムで消せる。 |
| ページを誤って拡大する | 作業領域内では起こさない。 |
| 初期状態が分からなくなる | `はじめから` で確認ダイアログなしに即時復帰できる。 |

### 6.3 教師の運用

- 教師は単元カードを開き、URLまたはQRを配るだけで開始できる。
- 児童への口頭説明は「開く → 問いを読む → うごかす → 分かったことを書く」までに収める。
- 児童作品の回収は初期版では必須にしない。必要な授業でだけ、画像保存または端末のスクリーンショットを既存の提出経路へ載せる。
- 共有・回収を導入する場合も、Classroom APIを使わない。別途、学校の許可したGoogle Workspace運用で設計する。

## 7. 性能と品質の受入基準

次の数値は初期目標である。実機（特に4GB端末）で測定し、未達なら機能追加より先に改善する。

| 観点 | 受入基準 |
|---|---|
| 初期表示 | 通常の校内回線で、最初の操作可能表示まで2秒以内を目標とする。 |
| 転送量 | 初期画面で必要なHTML・CSS・JS・画像の合計を500KB未満を目標とする。外部フォントを読み込まない。 |
| 操作 | 円のドラッグとペン描画中に、児童が認識できる遅延・引っかかりがない。 |
| 履歴 | 20回の戻す・やり直しで状態が壊れない。 |
| 回復 | ページ再読み込み後に、少なくとも初期状態へ必ず戻れる。 |
| 初見性 | 3年生が教師の個別支援なしで、60秒以内に指定した点を1回動かせる割合を授業試行で観察する。目標80%以上。 |
| 教師負担 | 初回の配布から活動開始まで、教師の端末操作を3手以内にする。 |

読み込み時間・操作遅延・初見性の目標には、現時点で当校端末による実測根拠はない。実装後の小規模試行で確かめ、数値を更新する。

## 8. テスト方針

### 自動テスト

- 円周上の点の距離計算
- 半径の変更が円の状態に正しく反映されること
- 課題データに必須項目があること
- `reset` が初期状態を復元すること
- 履歴の上限と `undo` の正しさ

### 手動テスト

- 指、タッチペン、マウスのすべてで円を動かせる
- ペンで書くとき、画面がスクロールしない
- 児童画面に未使用の道具が表示されない
- 画面幅の異なる端末でも問い・操作帯・作業領域が重ならない
- PNG出力に図形と手書きがともに含まれる
- ネットワークを切った後、すでに読み込んだ課題を操作できる

### 授業試行で観察すること

- 最初に児童が押す場所
- 質問が出た言葉・操作
- `もどす` が使われた場面
- どの補助表示が、発見を助けたか／答えを先取りしたか
- 紙だけの活動より、変形・比較が実際に増えたか

試行の結果、特定の機能が学習に寄与せず説明だけを増やすなら削除する。機能を残す根拠は、実装済みであることではなく、児童の思考を変えたこととする。

## 9. 実装の段階

### Phase 0 リポジトリ確認

1. 対象リポジトリ、既存の技術構成、デプロイ方法、ライセンスを確認する。
2. 実装前に、既存変更と衝突する可能性を短く報告する。
3. この文書を `docs/` へ置く。既存の仕様書がある場合は矛盾を列挙し、勝手に上書きしない。

### Phase 1 共通シェル

1. 単元カード → 導入 → 実験 → まとめの遷移を作る。
2. 操作帯、リセット、ヘルプ、配色・文字サイズの共通スタイルを作る。
3. モジュール読み込みと課題データのインターフェースを作る。

### Phase 2 円モジュール

1. 中心、半径、円周上の試行点をSVGで描画する。
2. 点と半径をドラッグできるようにする。
3. 補助線の表示・非表示、距離の比較を実装する。
4. ペン・消しゴム・履歴を重ねる。

### Phase 3 保存と検証

1. 図形と手書きをPNG出力する。
2. 自動テストと手動テストを実行する。
3. 4GB端末または同等条件で、読み込みとペン描画を確認する。

### Phase 4 授業試行後の改善

1. 質問・誤操作・動作不良を優先度順に直す。
2. 3年生の円で操作規則が定着してから、二等辺三角形を追加する。
3. UIを一般化し過ぎず、必要になった時点でだけ共通化する。

```text
児童画面には、課題ごとに必要な操作だけを最大3個表示してください。最初の対象は小学3年生の「円」であり、汎用図形ソフトを作らないでください。
```

## 11. 実装開始前に決めること

| 決定事項 | 現在の状態 | 実装への影響 |
|---|---|---|
| 配置するGitHubリポジトリ | 未決定 | Phase 0開始に必要。既存リポジトリ流用なら構成を確認する。 |
| 公開先 | 未決定 | 校内端末がアクセスできる方式を確認してから選ぶ。 |
| 最初の授業日・学級 | 未決定 | 試行の観察項目と回収方法を決める。 |
| 画像の回収経路 | 任意 | 初期版では必須にしない。必要になった時点で学校の既存手段に合わせる。 |

この4点が未決定でも、静的な円モジュールのローカル実装は開始できる。ただし公開・児童配布は確定しない。
